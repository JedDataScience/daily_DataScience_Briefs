## AI & Machine Learning

**Nvidia releases Nemotron 3.5 Super VL, an open 120B multimodal agent model**
Nvidia published Nemotron 3.5 Super VL on Oct 15. It is a hybrid mixture-of-experts model with 120B total parameters, of which only about 12B are active for each token. Nvidia released base, post-trained and 4-bit (NVFP4) checkpoints on Hugging Face, along with training recipes, reinforcement learning environments and open datasets, including 40 vision-language sets. Nvidia says it gets up to 5x the agentic-task throughput of other open models its size on a single GPU.
*Why it matters:* Releases that include data and recipes, not just weights, are the closest thing to a reproducible frontier-scale model you can study. MoE's "large total, small active" design is also a big reason inference costs keep falling.
[source](https://developer.nvidia.com/blog/nvidia-nemotron-3-5-super-vl-powers-specialized-agents-with-multimodal-reasoning/)

**Meta launches "Muse Wonder" frontier models**
On Oct 12 Meta unveiled Muse Wonder and Muse Wonder Full. It claims they match or beat the latest OpenAI and Anthropic models on many benchmarks, especially agentic work, memory and coding. Meta highlights "Active Memory," which keeps user information across chats, and "Active Focus," which keeps an agent working toward a goal when it hits obstacles. Access is through Meta's API and its Muse Code product, and Meta hasn't said whether the weights will be released.
*Why it matters:* Treat vendor benchmark claims as hypotheses until independent evaluations come in. Checking whether a reported improvement holds up outside the lab that reported it is core data science work.
[source](https://www.axios.com/2026/10/12/meta-new-ai-models-anthropic-openai)

## Research Highlights

**"A team of Gemini 4 Argon agents beats Minecraft" (arXiv:2610.22319)**
Researchers from Google DeepMind report that four Gemini 4 Argon agents defeated the Ender Dragon starting from a random Easy world in 27 hours 14 minutes. Each agent controlled one player through the open-source Mineflayer library, and the agents coordinated only through in-game chat and shared memory. No one assigned roles or wrote game-specific code. The agents wrote 2,783 programs and died 605 times, and the humans watching never had to step in.
*Why it matters:* This is a long-horizon benchmark where success requires thousands of chained decisions and constant debugging, much like real software projects. Expect evaluations like it to replace single-question benchmarks in the agent era.
[source](https://arxiv.org/abs/2610.22319)

**Sakana AI's "Agentic Scientist" (AI Scientist v3) is open source**
Sakana AI released the third version of its automated research system. It wraps coding agents in a pipeline: ideation agents write rubrics for what each experiment must show, parallel workers run under a fixed budget, ablation agents test which parts of the winning method matter, and every claim in the paper is tied to an evidence map. A paper co-discovered with the system was accepted as an oral presentation at ALIFE 2026. Across 70 research campaigns, the choice of model mattered more than the choice of harness, and AI reviewer scores correlated only moderately with actual numerical performance (r = 0.44).
*Why it matters:* The design is a checklist for doing ML experiments well: pre-register what success looks like, run ablations, and link every claim to evidence. It is also a reminder that AI "reviewer scores" are a noisy proxy for quality.
[source](https://pub.sakana.ai/agentic-scientist/)

## Tools & Libraries

**Polars 2.0: streaming by default, plus a silent row-order gotcha**
Polars 2.0 (released Oct 6) makes the streaming engine the default for `LazyFrame.collect()`. It can also spill to disk when RAM gets about 80% full, so larger-than-memory sorts and window functions just work. Other changes include stronger SQL support, a native `Map` dtype and stricter type checks. The big warning is that `join`, `group_by` and `unpivot` no longer guarantee row order unless you pass `maintain_order=True`, so pipelines that depend on order can change without raising an error.
*Why it matters:* If your coursework or projects use Polars, pin your version and compare outputs before upgrading. See today's concept for why order is never something to assume.
[source](https://pola.rs/posts/release-polars-2/)

**Perplexity open-sources SPACE, a sandbox for AI agents**
Perplexity made SPACE, the isolated environment it uses to run AI agents, open source on Oct 15. CoreWeave, Akamai and Crusoe will offer it to their customers. Perplexity says nine frontier models failed to break out in 118 attempts, but that result comes from the company itself and hasn't been independently verified.
*Why it matters:* If you let an LLM run code on data, for example as an "analyst agent," sandboxing is now basic infrastructure, much like a virtual environment.
[source](https://semafor.com/article/10/15/2026/perplexity-to-give-away-its-ai-security-software)

The demands seek documents on security incidents, safeguards, marketing and privacy policies, and the agency plans to make top executives testify. Separately, the EU's AI Office has sent its first formal requests for information to frontier-model providers under the AI Act.
*Why it matters:* Regulators on both sides of the Atlantic are moving from principles to evidence requests, which means monitoring and evaluation pipelines now carry legal weight.

They let it use crawlers to collect content from websites "associated with" Facebook, Instagram, WhatsApp or Messenger business accounts and use that content to train its products, including AI at Meta. ## Concept of the Day: Row Order Is Not a Guarantee (Deterministic Results)

**Intuition:** In relational databases and most modern dataframe engines, a table is a *set* of rows, not a list. Unless you explicitly sort, the engine may return rows in whatever order is fastest. That order depends on how the data is split across threads, how files were written, or which join algorithm ran. It can differ between versions, machines or even runs. That is exactly the change Polars 2.0's streaming engine makes.

**Tiny example:**
```sql
-- Not deterministic: "first 5" could change from run to run
SELECT customer_id, amount FROM orders LIMIT 5;

-- Deterministic: an explicit, unique sort key
SELECT customer_id, amount FROM orders
ORDER BY amount DESC, order_id   -- tie-breaker!
LIMIT 5;
```
```python
# Polars 2.0
df.group_by("team", maintain_order=True).agg(pl.col("score").mean())
# or simply sort at the end:
df.group_by("team").agg(pl.col("score").mean()).sort("team")
```

**When it matters:** any time you take the "first row" (`LIMIT`, `.head()`, `ROW_NUMBER()`, `drop_duplicates(keep="first")`), split train and test data by position, compute cumulative sums or lags, or compare outputs in tests.

**Common pitfall:** sorting on a column with ties. `ORDER BY amount` is still non-deterministic when two orders share the same amount. Always add a unique tie-breaker such as an ID. In window functions, `ROW_NUMBER() OVER (ORDER BY date)` with duplicate dates can quietly give different results on each run.
