## AI & Machine Learning

### 1. OpenAI's GPT-6.1 Terra: a cheaper middle model built for computer work

- **What happened:** On Oct 26, OpenAI released GPT-6.1 Terra, replacing GPT-5.6 Terra as its mid-tier model for "computer use" (reading the screen and clicking and typing across apps), visual reasoning and coding.
- **Key details:**
  - **Price:** $1 per million input tokens and $5 per million output tokens, half the price of GPT-5.6 Terra and of GPT-6.1 Sol ($2/$10). GPT-6 Astra, the top model, is $10/$50; GPT-6 Luna, the budget model, is $0.10/$0.50.
  - **Agents' Last Exam (max effort, self-reported):** Terra 60.0% at about $1.01 per task, vs GPT-6 Astra 59.3% ($7.24), GPT-6.1 Sol 58.6% ($2.00) and Claude Opus 5.5 63.2% ($8.82).
  - **OSWorld 2.1 (desktop agent tasks):** 74.2%, up from 57.1% for GPT-5.6 Terra, but below Claude Sonnet 5.5's 83.9%. **Terminal-Bench 4.0 (coding):** 50.3%, vs 21.5% for the old Terra.
  - OpenAI says Terra finishes tasks more than 3x faster than Astra and Sol. It is in ChatGPT and Codex for paid plans and in the API as `gpt-6.1-terra`.
- **Background:** **Reasoning effort** is a setting that controls how long a model "thinks" before answering. Higher effort usually means better answers but more tokens and more cost (see today's LLM concept).
- **The catch:** Nearly all numbers come from OpenAI. Cost per task depends on effort setting and workload. One analyst pointed out that cheaper tokens don't cut the cost of humans reviewing the output: in his example, about 5 extra seconds of review per task wiped out the savings. OpenAI still recommends Sol or Astra for the hardest coding.
- **Why it matters for you:** Look at the cost-per-task column, not just the score. Here Opus 5.5 scores 3.2 points higher than Terra but costs almost 9x more per task, a trade that rarely pays off in a high-volume pipeline. Get in the habit of benchmarking accuracy *and* cost on your own tasks.
- **Sources:** [InfoWorld](https://www.infoworld.com/article/4241006/openai-bets-on-ai-economics-with-lower-cost-gpt-6-1-terra.html) · [BleepingComputer](https://www.bleepingcomputer.com/news/artificial-intelligence/openai-launches-gpt-61-terra-with-3x-faster-ai-agents-50-percent-lower-pricing/)

### 2. Google DeepMind's Genie 4 generates interactive worlds, now with sound

- **What happened:** On Oct 27, Google DeepMind announced Genie 4, a real-time world model in research preview for trusted testers.
- **Key details:**
  - You move through a generated scene with keyboard controls and change it mid-session with text prompts, for example changing the weather, moving the camera or adding a character.
  - DeepMind calls it its first real-time world model to generate audio natively: ambient sound and character dialogue that responds to you. It also claims better physics (collisions, aerodynamics) and more natural human motion.
  - Gemini models run alongside it: one shapes how scenes look, and Gemini 3.8 Flash breaks a goal into steps and checks incoming frames to confirm each step worked.
  - DeepMind is using it in robotics research so tasks can be rehearsed in simulation first. Output carries Google's SynthID watermark. Google AI Ultra subscribers and early-access developers are next in line.
- **Background:** A **world model** learns to predict what happens next in an environment given an action. Instead of hand-coding a game engine, the model generates each new frame from what came before and what you did.
- **The catch:** DeepMind says detail and object permanence (things staying where they were) drift over long sessions or many edits, and text, spatial and audio accuracy still need work. No public specs on resolution or session length were in the coverage we could verify.
- **Why it matters for you:** World models are becoming a source of synthetic training data for robots and agents. The "drift over time" problem is the same error-accumulation issue you meet in any autoregressive model, including multi-step time-series forecasts.
- **Source:** [Resultsense](https://www.resultsense.com/news/2026-10-28-google-deepmind-genie-4-world-model/)

## Research Highlights

### 3. MLE-World: a small model that predicts what your ML script will print (arXiv:2610.37175)

- **What it is:** A paper posted Oct 27 by Brian Ko, Han Wang, Hejia Geng, Li Erran Li and Sherry Yang (with authors from Columbia, NYU, UIUC, Oxford and UW, per AI Weekly). Model weights and code are public.
- **The idea, simply:**
  - AI "research agents" try many candidate training scripts, and each one has to actually run, which is slow. MLE-World is Qwen3.5-4B fine-tuned to read a script and a data description and *predict* its terminal output: any error, the training log and the validation score. It also says how confident it is.
  - It was trained on 497,056 real program runs from agents working on 17 MLE-bench Lite tasks (Kaggle-style competitions).
  - An agent then uses the predictions to rank candidates, and only actually runs the ones where the predictor is unsure.
- **Results (self-reported):**
  - Predictions match the real output on 77.9% of held-out programs, vs 41.1% for much larger prompted models (not named in the abstract).
  - In agent search, a UCB-style policy (one that adds a bonus for exploring uncertain options) reached a 52.1 mean percentile vs 45.4 for the base AIDE agent. The best case was up to 22.1% higher mean performance, while saving 30–40% of real execution.
- **The catch:** Only 17 tasks, all from one benchmark family, so it may not generalize. "Up to 22.1%" is a best case. Skipping a run on a wrong high-confidence prediction can discard a good idea.
- **Why it matters for you:** This is a "surrogate model": a cheap model that stands in for an expensive experiment. The same trick powers Bayesian hyperparameter tuning. And predicting how a run will go before running it is a good habit for you too.
- **Sources:** [Hugging Face Papers](https://huggingface.co/papers/2610.37175) · [AI Weekly](https://aiweekly.co/alerts/mle-world-4b-predicts-ml-experiment-outcomes-at-779-accuracy)

### 4. Mistral's Timestral: small open forecasting models that run on a CPU

- **What it is:** Timestral is a family of four time-series "foundation models" (5M, 28M, 123M and 209M parameters) that Mistral released on Oct 15. Its paper page appeared on Hugging Face Papers this week (2610.37585), which is why it is trending again.
- **The idea, simply:**
  - **Zero-shot forecasting:** you give it the history of any series (sales, sensor readings, web traffic) and it forecasts the future without being trained on your data.
  - It is a transformer that reads the series in **patches** of 32 time steps (like words in a sentence) and handles up to 32,768 steps of history. You can tag extra series as **covariates**: past-only (e.g., yesterday's temperature) or known-future (e.g., scheduled holidays).
  - It outputs 21 **quantiles** instead of a single number, trained with pinball loss (today's ML concept). Pre-training used mostly synthetic series with trends, seasonality and noise, then a mix of real and synthetic data.
- **Results (self-reported):**
  - The 209M model ranks first among zero-shot models on GIFT-Eval (MASE 0.658 vs 0.667 for Google's TimesFM-3), TIME (MASE 0.626) and fev-bench (skill score 50.39 vs 48.99). Lower MASE is better.
  - On an 8-thread server CPU, a one-day forecast from three weeks of 15-minute data took about 10 ms with the 5M model and 140 ms with the 209M model.
- **Background:** **MASE** (mean absolute scaled error) divides your error by the error of a naive "repeat the last season" forecast, so a value below 1 means you beat the naive baseline.
- **The catch:** Margins are small (0.658 vs 0.667 is about 1.3%). Code is Apache 2.0, but the weights use a *modified* MIT license that excludes companies with more than $20M in monthly revenue. That matters if you plan to use it at a large employer.
- **Why it matters for you:** Forecasting is one of the most common data science jobs. A tiny pretrained model that gives prediction intervals on a laptop is a strong baseline to try before building your own. Always compare against a seasonal-naive forecast on your own data with a time-based split.
- **Sources:** [Mistral AI](https://mistral.ai/news/timestral/) · [Braindetox (summary of sizes, license and usage)](https://braindetox.kr/en/posts/timestral_mistral_time_series_model.html)

**Also noted:** Axiom Math says its AI agents produced a complete Lean formalization of the Classification of Finite Simple Groups (a roughly 15,000-page proof) in about 24 days: 43.1M lines, with 34 notable deviations from the published record found along the way. All of this is self-reported ([Unite.AI](https://www.unite.ai/axiom-math-releases-43-1m-line-lean-proof-of-group-classification/)). And Goodfire's mid-October essay "Neural Networks Are Already Clean," which argues most neurons in CNNs like InceptionV1 and ConvNeXt are interpretable, is still drawing debate ([Goodfire](https://already-clean.goodfire.com/)).

### 5. Critical MLflow bug: upgrade to 3.17.0

- **What happened:** On Oct 27, CVE-2026-116692 was published for MLflow, the popular open-source tool for tracking experiments and models. It is rated 9.8 out of 10 (critical).
- **Key details:**
  - **Affected:** versions 3.12.0rc0 up to (not including) 3.17.0. **Fixed in 3.17.0.**
  - The bug is in how MLflow loads "third-party scorers" (plug-in evaluation code in its GenAI features). It accepts any submodule *under* an allowed package rather than only exact matches. An attacker can upload a Python file as an artifact into a writable allowed package, then call the scorer endpoint so the server imports and runs it.
  - On servers with authentication off (common for local or lab setups), no login is needed. With basic auth, the attacker needs an account that can create experiments and upload artifacts.
  - No public exploit was known at publication. Related: Hugging Face's diffusers 0.42.1 (Oct 27) also patched a `trust_remote_code` bypass in `from_pretrained`.
- **Background:** **Remote code execution (RCE)** means an attacker can run their own commands on your machine. It is about the worst kind of bug, because the attacker can then read data, steal credentials or install malware.
- **Why it matters for you:** Run `pip install -U "mlflow>=3.17.0"` and never expose an MLflow server to the internet without authentication. ML tooling is now a real attack target, so pin and update dependencies like any production software.
- **Sources:** [Strix (CVE record)](https://www.strix.ai/cve/CVE-2026-116692) · [TheHackerWire](https://www.thehackerwire.com/cve-2026-116692-mlflow-deserialization-flaw-leads-to-remote-code-execution/)

## Concepts of the Day

### Machine Learning: Quantile Forecasts and Pinball Loss

**In one sentence:** Instead of predicting one "best guess," a quantile model predicts a value the outcome will fall below a chosen fraction of the time (say 90%), and it is trained with the **pinball loss**.

**Intuition:** A coffee shop deciding how many croissants to bake doesn't care about the average day. It wants a number that covers demand on 9 days out of 10. Running out (under-predicting) is costly, while a few leftovers are cheap. The 0.9 quantile is that number.

**Formula / Tiny example:** For quantile *q*, true value *y* and prediction *ŷ*:
- If *y* ≥ *ŷ* (you under-predicted): loss = *q* × (*y* − *ŷ*)
- If *y* < *ŷ* (you over-predicted): loss = (1 − *q*) × (*ŷ* − *y*)

With *q* = 0.9 and *y* = 10: predicting 8 costs 0.9 × 2 = **1.8**, while predicting 12 costs 0.1 × 2 = **0.2**. Under-predicting is 9 times more expensive, so the model learns to aim high. At *q* = 0.5 both cost 1.0, and the loss becomes half the absolute error, which gives you the median.

```python
from sklearn.ensemble import GradientBoostingRegressor
from sklearn.metrics import mean_pinball_loss

lo = GradientBoostingRegressor(loss="quantile", alpha=0.1).fit(X_tr, y_tr)
hi = GradientBoostingRegressor(loss="quantile", alpha=0.9).fit(X_tr, y_tr)
# lo.predict(X) to hi.predict(X) is an 80% prediction interval
print(mean_pinball_loss(y_te, hi.predict(X_te), alpha=0.9))
```

**When it's used:** Demand and inventory planning, energy load forecasting, delivery-time estimates ("arrives by…"), and risk measures like Value at Risk in finance.

**Common pitfalls:** (1) Training separate quantile models can produce "crossing" quantiles, where the 0.1 prediction ends up above the 0.9 one. Check for this and sort the predictions if needed. (2) Check **coverage** on test data: about 80% of true values should fall inside an 80% interval. If only 60% do, the interval is too narrow.

**In today's news:** Timestral (story 4) outputs 21 quantiles per time step and is trained with exactly this loss.

### LLMs: Test-Time Compute (Best-of-N)

**In one sentence:** Test-time compute means spending extra computation when the model *answers* (thinking longer, or generating several answers and picking the best) instead of only making the model bigger during training.

**Intuition:** On an exam, you can either study more beforehand (training) or use your time to draft three solutions and check which one holds up (test time). Both raise your score, and the second doesn't require learning anything new.

**Formula / Tiny example:** In **Best-of-N**, you sample *N* answers and a checker (verifier) picks one. If one attempt solves a problem with probability 0.3 and the checker is perfect, the chance that at least one of *N* attempts is right is 1 − 0.7^N:
- N = 1: 0.30
- N = 5: 1 − 0.168 = **0.83**
- N = 10: **0.97**

But cost grows linearly: 10 samples cost about 10 times as much.

```python
answers = [llm.generate(prompt, temperature=0.8) for _ in range(5)]
best = max(answers, key=verifier_score)   # or majority vote
```

**When it's used:** Reasoning models' "effort" settings, coding agents that run unit tests on several candidate patches, majority voting on math problems, and agents that search over plans.

**Common pitfalls:** (1) The math above assumes a perfect checker. With a weak verifier, larger *N* can make results worse, because the checker gets fooled by confident wrong answers. (2) Comparing models at different effort levels or sample counts isn't fair. Always report the compute or cost alongside the score.

**In today's news:** GPT-6.1 Terra's scores change with reasoning effort (story 1), and MLE-World (story 3) is a cheap predictor that lets an agent rank many candidates before paying to run them.

### Deep Learning: Convolutional Neural Networks (CNNs)

**In one sentence:** A CNN is a neural network that slides small learned filters (kernels) across an image, so the same pattern detector, such as for an edge or a curve, is reused at every location.

**Intuition:** Think of a small magnifying glass that you slide across a photo, looking for one thing, like a vertical edge. You use the same glass everywhere instead of building a separate detector for every pixel position. Stacking layers lets early filters find edges, middle ones find textures and shapes, and late ones find whole objects.

**Formula / Tiny example:** A 3×3 vertical-edge kernel `[[1,0,-1],[1,0,-1],[1,0,-1]]` on the top-left 3×3 patch `[[1,2,0],[0,1,2],[1,0,1]]`: multiply element by element and add. The left column gives 1+0+1 = 2, the middle column is multiplied by 0, and the right column gives −(0+2+1) = −3, so the output is 2 − 3 = **−1**. Output size = (W − K + 2P)/S + 1, so a 32×32 image with a 3×3 kernel, no padding (P = 0) and stride 1 (S = 1) gives 30×30.

Weight sharing saves parameters. `nn.Conv2d(3, 16, kernel_size=3)` has 16 × (3×3×3) + 16 = **448** parameters. A fully connected layer from a 32×32×3 image to 16 units needs 3,072 × 16 + 16 = **49,168**.

```python
import torch.nn as nn
model = nn.Sequential(
    nn.Conv2d(3, 16, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),   # 32x32 -> 16x16
    nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),  # 16x16 -> 8x8
    nn.Flatten(), nn.Linear(32 * 8 * 8, 10))
```

**When it's used:** Image classification, medical imaging, object detection, OCR, audio spectrograms, and 1-D convolutions on time series and sensor data.

**Common pitfalls:** (1) Getting the size math wrong before the `Linear` layer, which causes shape-mismatch errors. Print `x.shape` after each block. (2) Training from scratch on a small dataset when a pretrained CNN (ResNet, ConvNeXt) with transfer learning would work far better.

**In today's news:** Goodfire's essay (Also noted, Research) studies the neurons of the CNNs InceptionV1 and ConvNeXt and argues most of their last-layer neurons can be understood.
