## AI & Machine Learning

### 1. Anthropic's FlashProve: a cryptographic receipt for AI answers

- **What happened:** On Nov 3, Anthropic published research and code for FlashProve, a system that lets anyone check that a given output came from a given model.
- **Key details:**
  - The lab publishes a "fingerprint" (a cryptographic commitment to the exact weights). Each answer can come with a proof that those committed weights produced it. Checking the proof doesn't require the weights.
  - Tested on Llama 4 Maverick (400B parameters, about 17B active per token). Reported throughput is about 110 tokens/s of proving on one 80 GB H100, with a proof of about 19 MB for a 1,024-token request. Verifying takes seconds on a CPU.
  - The cost is high: proving takes roughly 70–95x the GPU time of normal generation.
  - The motivation is model substitution. A provider could quietly swap in a cheaper model to save money, or a stronger one to inflate test results.
- **Background:** A **zero-knowledge proof** convinces you a statement is true ("these committed weights produced this text") without revealing the secret behind it (the weights).
- **The catch:** It's a research prototype that Anthropic has no plans to deploy. It supports only greedy decoding (no sampling or temperature), a 1,024-token context, and integer arithmetic.
- **Why it matters for you:** If you benchmark models through an API, you are trusting that the API serves the model it names. This is the first fast attempt at checking that claim. It's also a good reminder to log the model name, version and date with every result.
- **Sources:** [TechCrunch](https://techcrunch.com/2026/11/03/anthropic-is-working-on-a-system-to-prove-ai-models-identity/) · [AlphaSignal technical summary](https://alphasignal.ai/news/anthropic-s-flashprove-cryptographically-proves-which-ai-model-answered-you)

### 2. Revolut cut AI coding costs about 90% by self-hosting an open model

- **What happened:** At the AI Engineer conference in New York (reported Nov 3), Revolut said it made self-hosted GLM models its default coding assistant for about 2,000 engineers, instead of mainly paying for commercial tools.
- **Key details:**
  - It started on GLM-5.1 (about 754B total, 40B active parameters) and now runs GLM-5.3 on 56 Nvidia B200 GPUs.
  - Self-hosted cost was about $0.30 per million tokens, roughly a tenth of what Codex or Claude Code cost the company.
  - Revolut's ops lead said tuning mattered more than adding GPUs, including 4-bit (NVFP4) quantization and splitting prompt processing from token generation onto separate machines.
  - GLM is text-only, so a router still sends image tasks to commercial models such as Gemini or GPT.
- **The catch:** The productivity figures (60% better coding time, 70% better lead time) are company-reported and weren't measured against a control group.
- **Why it matters for you:** Cheap tokens changed how the tools were used, not only what they cost. Engineers stopped rationing and used AI for debugging and tickets. Serving open-weight models (see Story 5) is a growing MLOps skill.
- **Source:** [The Register](https://theregister.com/ai-and-ml/2026/11/03/british-fintech-revolut-slashes-ai-coding-costs-10x-by-cutting-out-claude-and-going-self-hosted/5307345?amp=)

## Research Highlights

### 3. StateBench: can models keep track of things that change? (Ai2)

- **What it is:** a benchmark Ai2 released on Nov 3 that tests "state tracking," meaning following how values change across a long document.
- **The idea, simply:**
  - It sorts problems into four levels. A value set once (`x = 4`). A value overwritten (`x = 4`, later `x = 2`). A running update (`x = x + 5`). Variables that copy or swap with each other (`x = y`), like following a ball under shuffled cups.
  - Gemini 3.8 Flash, Claude Opus 5.5, GPT-6 Sol and GPT-6 Luna handle the first two levels well. On the hardest level with the longest inputs, they fall to **13% or lower**.
  - Ai2 also trained small 275M-parameter models from scratch on up to 256 assignments and tested them on up to 64,000, which is 250x longer. Recurrent and hybrid designs (Gated DeltaNet) generalized almost perfectly on the first three levels. Transformers got worse as inputs grew and never learned the hardest level.
- **The catch:** Changing the format alone (a spreadsheet edit instead of `x = 4`) dropped some small models to chance. Results depend on how a problem is phrased.
- **Why it matters for you:** A long context window doesn't mean the model reliably tracks what's in it. Test the actual pattern your task needs, such as account balances or inventory counts. See today's deep learning concept.
- **Sources:** [Ai2 on Hugging Face](https://huggingface.co/blog/allenai/statebench) · [arXiv:2611.03094](https://arxiv.org/abs/2611.03094)

### 4. The shelf life of an LLM finding is about 15 months (Stanford)

- **What it is:** Owen Queen and James Zou re-ran 50 widely cited claims about LLM behavior on 20 models from eight developers, released between July 2024 and September 2026. Published Nov 2.
- **The idea, simply:**
  - For each claim they rebuilt the original experiment and measured the effect on each model, scaled so 1 equals the original paper's effect and 0 means it's gone. Then they fit a trend line against model release date.
  - A claim counted as "expired" if its effect shrank to a fifth of the original or less.
- **Results:**
  - 44% of claims expired, 34% weakened, 16% persist and 6% got stronger.
  - For the 22 expired claims, the average time to expire was 15.7 months (median 14.7).
  - Capability failures faded fastest. Fabricated citations fell from 55% in a 2023 study to about 1% or less on current models. Tendencies such as LLM judges preferring their own outputs, or flattering the user, lasted longer.
- **Why it matters for you:** "LLMs can't count letters" may be true for one model in one year and false the next. When you cite or write a finding, record the model, version and date, and share your prompts and code so others can re-run it. See today's ML concept.
- **Source:** [Stanford project page](https://zou-group.github.io/llm-claims-shelf-life/)

## Tools & Libraries

### 5. vLLM 0.33: faster serving, CUDA 13 only

- **What happened:** On Nov 2, vLLM, the most widely used open-source engine for serving LLMs, released v0.33.0. It includes 927 commits from 389 contributors, 122 of them first-time contributors.
- **Key details:**
  - Moves to PyTorch 2.14 and **drops CUDA 12.9**. Release wheels and Docker images now need CUDA 13.0.
  - More **speculative decoding** options (see the LLM concept), including an opt-in "lossy" verification mode. The older Medusa and MLP-speculator methods were removed.
  - New model support includes Reflection's Beam, Meta's Muse Spark Open and several small OCR and embedding models.
  - Requests sent while generation is paused now return an HTTP 503 error, and the Rust front end rejects flags it doesn't support instead of silently ignoring them.
- **The catch:** The speedups in the notes (for example 39–48% faster first tokens on 100k-token inputs) come from individual pull-request benchmarks on specific hardware.
- **Why it matters for you:** Pin your versions. A `pip install -U vllm` on a machine with older CUDA drivers can break a working setup. Read the "breaking changes" section before you upgrade any ML library.
- **Source:** [vLLM release notes on GitHub](https://github.com/vllm-project/vllm/releases/tag/v0.33.0rc3)

- **Why it matters for you:** Where your data came from matters legally, and lawsuits are now reaching the suppliers of web data, not only model makers. If you scrape data for a project, record the source and its terms.

## Concepts of the Day

### Machine Learning: Concept Drift

**In one sentence:** Concept drift is when the relationship between your inputs and the correct answer changes over time, so a model that was accurate when you trained it slowly gets worse.

**Intuition:** A map of a city is right on the day it's printed. Then roads close and new ones open. The map isn't broken; the city changed. Models are maps of the world at training time.

**Formula / Tiny example:** A fraud model scores 92% accuracy in January. Scammers change tactics, and June's labeled data gives 81%. The inputs might look similar, but what "fraud" looks like has changed. A simple monitor compares accuracy on recent labeled data with a baseline:

```python
monthly = df.groupby("month").apply(lambda g: (g["pred"] == g["label"]).mean())
drifting = monthly[monthly < 0.92 - 0.05]   # alert when 5+ points below baseline
```

June (0.81 < 0.87) triggers an alert, which is the cue to retrain on recent data.

**When it's used:** Fraud detection, demand forecasting, spam filters, credit scoring. Anywhere the world or user behavior changes.

**Common pitfalls:** Confusing it with *data drift*, where the input distribution shifts (for example, younger customers) but the input–label relationship may not. Also, randomly splitting time-ordered data for validation hides drift. Validate on a later time period.

**In today's news:** Story 4 shows drift from the other side: the models changed, so 44% of published "facts" about them expired within about two years.

### LLMs: Speculative Decoding

**In one sentence:** Speculative decoding speeds up text generation by letting a small, fast "draft" model guess several tokens ahead, then having the big model check all the guesses in a single pass.

**Intuition:** A junior writer drafts the next few words of a sentence, and the senior editor reads them at once, keeping everything up to the first word they'd change. Reading is faster than writing from scratch.

**Formula / Tiny example:** The draft model proposes *k* tokens. If each guess is accepted with probability α, the expected number of tokens produced per big-model pass is (1 − α^(k+1)) / (1 − α). With α = 0.8 and k = 4: (1 − 0.8⁵) / 0.2 = (1 − 0.328) / 0.2 ≈ **3.36 tokens per pass**, instead of 1. Because rejected tokens are replaced using the big model's own probabilities, the output follows the same distribution as the big model alone. In Hugging Face, `model.generate(**inputs, assistant_model=small_model)` turns it on.

**When it's used:** Production LLM serving (vLLM, TensorRT-LLM), chat apps and coding assistants where response speed matters.

**Common pitfalls:** Expecting a speedup with any draft model. If the draft disagrees with the big model often (low α), you pay for drafting and get little back. It also helps most at small batch sizes. Busy servers that are already processing many requests gain less.

**In today's news:** Story 5. vLLM 0.33 adds new draft methods and an opt-in "lossy" check that accepts near-matches, giving up the exact-same-output guarantee for speed.

### Deep Learning: Linear Attention and Recurrent State

**In one sentence:** Linear attention replaces the transformer's "compare every token with every earlier token" step with a fixed-size memory matrix that is updated once per token, like an RNN.

**Intuition:** Standard attention is a notebook: you keep every page and reread all of them for each new word. Linear attention is a whiteboard of fixed size: you update it as you go and read only the board.

**Formula / Tiny example:** For a 64,000-token input, full attention compares about 64,000² ≈ 4.1 billion token pairs, and its KV cache grows with every token. A linear-attention layer with head size d = 128 keeps a 128 × 128 state, which is 16,384 numbers no matter how long the input. The "delta rule" used in DeltaNet overwrites old values instead of piling new ones on top:

```python
S = torch.zeros(d, d)                         # memory: maps keys -> values
for k, v, q, beta in zip(K, V, Q, betas):
    S = S + beta * torch.outer(v - S @ k, k)  # replace old value stored at key k
    out = S @ q                               # read memory with query q
```

That is exactly what `x = 4` followed by `x = 2` needs. **Gated** DeltaNet also adds a forget gate that fades old memories.

**When it's used:** Long-context and hybrid models that mix a few full-attention layers with many linear layers to save memory (for example Olmo Hybrid and several recent open models).

**Common pitfalls:** Assuming a fixed-size memory is always better. It can't recall exact details from far back as well as full attention, which is why most models are hybrids.

**In today's news:** Story 3. On StateBench, the Gated DeltaNet and hybrid models tracked changing values far beyond their training length, while pure transformers did not.
