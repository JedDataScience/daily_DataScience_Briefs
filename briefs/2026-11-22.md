## AI & Machine Learning

### 1. Inkling 2 Mini: a small open model that reuses its own layers

- **What happened:** On Nov 20, Thinking Machines Lab (Mira Murati's startup) released Inkling 2 Mini, an open-weights mixture-of-experts model built as a "looped" transformer.
- **Key details:**
  - 26.4B total parameters with 3.4B active per token. Because some layers run three times, the company says each token uses about 5.4B weight activations. The whole model takes about 20 GB.
  - It stores 24 layers in four blocks of 6. The first and last blocks run once; the two middle blocks (12 layers) run three times: 6 + 12×3 + 6 = 48 layer applications per token.
  - Self-reported scores: 79.2% on SWE-bench Verified and 48.2% on DeepSWE v1.1 (Qwen3.8-27B: 42.2%). It trails Qwen3.8-27B on two instruction-following tests (50.0% on MultiChallenge, 33.4% on ComplexConstraints).
  - Independent check: Artificial Analysis gives it 20 on its Intelligence Index, the same as Qwen3.8 27B. It used about 38% more output tokens (≈152K vs ≈110K per task) but cost $0.59 and 9.0 minutes per task vs $3.53 and 38.2 minutes. Artificial Analysis lists an Apache 2.0 license and a 1M-token context.
  - Weights are on Hugging Face, with vLLM, Ollama, Unsloth and llama.cpp builds.
- **Background:** "Active parameters" are the weights actually used for one token. In a mixture-of-experts model, a router picks a few experts per token, so most weights sit idle at any moment.
- **The catch:** The benchmark table is the company's own. Artificial Analysis's cost figures use Thinking Machines' first-party pricing, so other hosts will differ.
- **Why it matters for you:** A model with frontier-ish coding scores in about 20 GB is something you can actually run and fine-tune. It also shows that "parameter count" and "compute per token" are different numbers (see today's deep learning concept).
- **Source:** [Thinking Machines Lab](https://thinkingmachines.ai/news/inkling-2-mini/), [Artificial Analysis](https://artificialanalysis.ai/articles/inkling-2-mini)

### 2. Gemini API agents can now load tools only when they need them

- **What happened:** On Nov 19, Google put "Tool Retrieval" into preview in the Gemini API's Interactions API, for Gemini 3.6 and later, including all Gemini 4 models.
- **Key details:**
  - You mark tools with `defer_loading: true` and add a `tool_search` tool. The model sees only each deferred tool's name and description; the full parameter schema is loaded when the model decides to use it.
  - It also works with remote MCP servers (a standard way to plug outside tools into an AI model). No separate fee; loaded schemas are billed as normal input tokens for the rest of the conversation.
  - PPC Land, reading Google's docs, reports about 26 tokens per deferred tool in early testing. For 100 tools that's about 2,600 tokens per request, or roughly $0.004 at $1.50 per million input tokens.
- **The catch:** Google gives no savings or accuracy numbers and tells developers to measure on their own traffic. Per PPC Land, loaded schemas can't be unloaded later in a conversation.
- **Why it matters for you:** In agent apps, the tool list itself can eat a big chunk of the context window. Showing the model a short menu and fetching details on demand is the same idea as retrieval in RAG, applied to tools.
- **Source:** [Google blog](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/), [PPC Land](https://ppc.land/google-shrinks-idle-tools-in-gemini-agents-to-about-26-tokens-each/)

## Research Highlights

### 3. Architecture differences show up only at real scale (arXiv:2611.24963)

- **What happened:** Zeyuan Allen-Zhu posted "Physics of Language Models: Part 4.2" (submitted Nov 12, in arXiv's Nov 20 cs.CL listing), a study of 64 pretraining runs from 1.3B to 8B parameters on 1–2 trillion tokens.
- **Key details:**
  - At "academic" scale (1.3B parameters, 100B tokens), carefully tuned architectures looked almost the same. At 1–2T tokens, real gaps appeared.
  - Adding "Canon layers," which mix each token with its close neighbors, saved about 30% of pretraining tokens for the same MMLU score at 8B. If a model needed 1T tokens before, that's roughly 700B with Canon.
  - Linear-attention models that matched Transformers on benchmarks still couldn't reliably pull a fact out of a short 500-token context. No model, of any type, reliably beat random guessing on a simple two-step ("two-hop") question.
  - One 8B run cost roughly $100K.
- **The idea, simply:**
  - Benchmarks like MMLU mostly test stored knowledge, so they can miss whether a model can *use* information in its prompt.
  - Tiny synthetic tasks (under 100M parameters) predicted which architectures would win at 8B, at a fraction of the cost.
  - The author's practical advice: put examples of in-context reasoning into pretraining data early, not only during later fine-tuning.
- **The catch:** Single author; results, recipes and code have been public on GitHub since Dec 2025, so parts of this aren't brand new.
- **Why it matters for you:** A great lesson in evaluation: a single headline score can hide a skill the model doesn't have. Test the specific ability you care about.
- **Source:** [arXiv](https://arxiv.org/abs/2611.24963)

### 4. LLMs know a question is unstudied but rarely say so (arXiv:2611.23546)

- **What happened:** In a cs.CL paper submitted Nov 17, Guy Zyskind tested whether AI models tell you when a research question is still open.
- **Key details:**
  - On 40 questions taken from newly accepted papers, GPT-6 Astra correctly judged 98% as unstudied when asked directly, but said so plainly in only 8% of its ordinary answers.
  - Across six frontier systems (22 models in all), the paper reports gaps of 30 to 90 percentage points between what a model "knows" and what it reports.
  - Given the papers that answer a question, models spotted already-studied questions 88–100% of the time. A corrected prompting procedure raised Astra's clear reporting from 8% to 95%.
- **The idea, simply:**
  - Ask the same question two ways: "Has this been studied?" versus a normal "Tell me about X."
  - The difference shows the model often makes new ideas sound like settled literature, which can mislead you about novelty.
- **The catch:** 40 questions is a small set, and a single-author preprint.
- **Why it matters for you:** If you use an LLM for a literature review, ask explicitly "is this an open question?" and check the citations yourself.
- **Source:** [arXiv](https://arxiv.org/abs/2611.23546)

**Also noted:** A study of 2.5 million full-text papers in five fields (2015–2025) finds that, apart from word-frequency shifts, most pre-2023 trends in science simply continued after ChatGPT ([arXiv:2611.22975](https://arxiv.org/abs/2611.22975)).

## Industry & Policy

### 5. ChatGPT's Saturday outage traced to two database replicas

- **What happened:** On Nov 21, from 1:48 to 5:21 PT (about 3.5 hours), ChatGPT and the API had elevated errors, peaking at a 75% failure rate for both free and paid ChatGPT users. OpenAI has published a write-up.
- **Key details:**
  - Scheduled maintenance on a Postgres database service made *both* of its read replicas fail at once. That service backs OpenAI's "Primary API," which handles user and service-to-service authentication, so many requests failed.
  - Attempts to revive the replicas or bring replacements up in other regions failed. The fix was bringing two new replicas online in the same region with the database provider.
  - Follow-ups: a pause on similar maintenance, a pre-maintenance review, spare standby capacity, work on replica lag (which grew "unboundedly"), and a redundancy review of the whole stack. OpenAI wrote, "we came up short here."
- **Background:** A *read replica* is a copy of a database that serves read queries so the main (primary) copy isn't overloaded. If the system can't run without the replicas, they're no longer optional backups.
- **Why it matters for you:** ML systems fail at the plumbing more often than at the model. Knowing basic database ideas (replicas, failover, lag) is part of shipping anything real.
- **Source:** [OpenAI status](https://status.openai.com/incidents/01JMYB602A6H2E04Y1497J434X/write-up)

## Concepts of the Day

### Machine Learning: Feature Selection (Filter, Wrapper, Embedded)

**In one sentence:** Feature selection means choosing a subset of your input columns to train on, dropping ones that add noise, cost or risk without helping predictions.

**Intuition:** Packing for a trip: you don't bring everything you own. You keep what you'll actually use, because extra luggage slows you down.

**Formula / Tiny example:** Three families:
- *Filter*: score each feature alone (correlation, mutual information) and keep the top k. If |correlation| with the target is 0.62, 0.05 and 0.41 for features A, B, C, keeping k = 2 gives **A and C**.
- *Wrapper*: try subsets with a model. Checking every subset of 20 features means 2²⁰ = **1,048,576** models; forward selection of 5 features needs only 20 + 19 + 18 + 17 + 16 = **90**.
- *Embedded*: the model selects while training, e.g. L1 (Lasso) pushes useless weights to exactly zero.

```python
from sklearn.pipeline import make_pipeline
from sklearn.feature_selection import SelectKBest, mutual_info_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
pipe = make_pipeline(SelectKBest(mutual_info_classif, k=10), LogisticRegression(max_iter=1000))
print(cross_val_score(pipe, X, y, cv=5).mean())   # selection happens inside each fold
```

**When it's used:** Wide datasets (genomics, text counts, sensor logs), cutting the cost of collecting features, and making models easier to explain.

**Common pitfall(s):** Selecting features on the full dataset *before* cross-validation leaks test information and inflates scores; put selection inside the pipeline as above. And a feature that's weak alone can be strong in combination, which filter methods miss.

**In today's news:** Gemini's Tool Retrieval (story 2) applies a similar idea to prompts: give the model only the tool details it needs instead of everything.

### LLMs: In-Context Learning (Few-Shot Prompting)

**In one sentence:** In-context learning is when an LLM picks up a task from examples placed in the prompt, with no change to its weights.

**Intuition:** Showing a new coworker three filled-in forms before handing them a blank one. They learn the pattern from the examples, not from a training course.

**Formula / Tiny example:** A sentiment prompt with examples:

```python
prompt = """Review: "Battery died in a day." -> negative
Review: "Fast shipping, works great." -> positive
Review: "Screen is fine, speakers are awful." -> negative
Review: "Exactly what I needed." ->"""
# The model should continue with " positive"
```

Examples cost tokens on every call. Four examples of 60 tokens = 240 extra tokens; at 1,000 requests a day that's 240,000 tokens, or $0.36/day at $1.50 per million input tokens. "Zero-shot" means no examples; "few-shot" means a handful.

**When it's used:** Quick classifiers and extractors without fine-tuning, setting an output format, and teaching an agent a tool's style of use.

**Common pitfall(s):** Results can swing with example order and label balance (if most examples say "negative," the model leans negative). And using your test items as examples makes your evaluation meaningless.

**In today's news:** Story 3 found some models with strong benchmark scores still couldn't reliably use facts from a 500-token prompt, and advises putting in-context examples into pretraining early.

### Deep Learning: Weight Sharing and Looped Layers

**In one sentence:** Weight sharing means using the same set of weights in more than one place in a network, so the model gets more computation without more parameters.

**Intuition:** Re-reading a hard paragraph three times. It's the same "reader" each time, but each pass builds on what you understood the last time.

**Formula / Tiny example:** A fully connected layer with width 1,000 has 1,000 × 1,000 = **1,000,000** weights (ignoring biases). Four separate layers = 4,000,000 weights. One layer looped 4 times = **1,000,000** weights, but the same compute as four layers.

```python
import torch, torch.nn as nn
class Looped(nn.Module):
    def __init__(self, d, loops=3):
        super().__init__()
        self.block, self.loops = nn.Linear(d, d), loops
    def forward(self, x):
        for _ in range(self.loops):
            x = x + torch.relu(self.block(x))   # same weights every pass
        return x
```

**When it's used:** CNNs share one small filter across every image position; RNNs reuse the same weights at every time step; ALBERT and Universal Transformers share layers; and now looped LLMs like Inkling 2 Mini.

**Common pitfall(s):** Fewer parameters doesn't mean faster: compute and activation memory still grow with the number of loops. Gradients from every pass add up on the shared weights, which can make training less stable, so careful initialization or gating helps.

**In today's news:** Inkling 2 Mini (story 1) stores 24 layers but applies 48 per token by looping its middle 12 three times, behind a learned gate that starts closed.
